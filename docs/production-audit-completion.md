## Resume changes and CI failure mechanism

Both original runs (`39175609742` push and `39175627158` pull_request) successfully completed `npm test`, Prisma generation/validation, no-emit typecheck and the schema/migration diff. The failing step was **`git show --format= --check HEAD`**, exit2. Its diagnostics enumerate inherited CRLF/trailing whitespace and generated Prisma comments, not failed tests.

`actions/checkout` defaults to depth1. Git treats a shallow boundary as a root commit, so the whitespace check compares the entire tree with the empty tree instead of the implementation commit with its parent. Reproduced locally using a depth1 `file://` clone of the exact branch: exit2 before fetching parents, exit0 after `fetch --unshallow`, without changing any file. The workflow now fetches full history. The whitespace step remains present and unchanged; no test, schema or whitespace check was disabled. The PostgreSQL health command now names the actual test user/database, avoiding misleading repeated `role root does not exist` diagnostics.

Added packaging CI builds both images and executes non-root dependency/asset checks and Prisma schema validation inside the migration image. Its first run exposed npm retaining TypeScript through Prisma's optional peer graph despite `--omit=dev`; the API image now also omits peer-only and optional packages. The smoke test continues to require build tooling absent and actual runtime dependencies importable. No production image is pushed or deployed by this workflow.

Resume adds six real startup-import tests and two financial regressions described above. The original 155-file implementation manifest remains a historical inventory of `fb4f2af`; these follow-up changes and the recovered report/completion report are additional scope. Existing migrations and dependency versions are unchanged.
